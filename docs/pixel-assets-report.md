### 아잉 스프라이트 8장 — 96×96, 투명

`aing-idle` · `aing-walk-1` · `aing-walk-2` · `aing-jump` · `aing-sit` ·
`aing-think` · `aing-wave` · `aing-celebrate` — 각 5.2~5.8KB.

**1차는 실패했고 8장 전부 다시 만들었습니다.** 1차 결과물은 바이저 헤드밴드가 없고
외곽선이 없고 몸이 길쭉한 고양이라 아잉으로 읽히지 않았습니다. 원인은 셋이었습니다 —
개정 전 계약이 바이저를 빼라고 했고, 공통 규칙의 `no outline`을 캐릭터에까지 적용했고,
체형 지시가 없었습니다.

개정된 계약의 일곱 가지를 프롬프트에 전부 명시해 다시 뽑았고, 결과물에서 전부 확인했습니다:

| # | 특징 | 확인 |
|:-:|---|:-:|
| 1 | 이마를 가로지르는 넓은 하늘색 **바이저 헤드밴드** (뇌 아이콘만 제거) | ✓ |
| 2 | 양쪽 **파란 원형 헤드폰** (글자 A만 제거) | ✓ |
| 3 | 실루엣 전체를 두르는 **굵은 남보라 외곽선** | ✓ |
| 4 | **마시멜로 체형** — 머리 약 45%, 둥근 물방울 몸, 짧고 뭉툭한 팔다리 | ✓ |
| 5 | **위로 말린 갈고리 꼬리** | ✓ |
| 6 | 큰 파란 눈 + **흰 하이라이트 두 점**, 분홍 삼각 코, **연분홍 볼 홍조** | ✓ |
| 7 | 귀 흰 바깥 · 연분홍 안쪽 | ✓ |

공통 프롬프트 접두의 `no outline`은 **스프라이트에서만 뺐습니다.** 계약 섹션 C가 그 규칙을
배경과 소품에만 적용한다고 명시하기 때문입니다. 배경·소품 프롬프트는 접두 그대로입니다.

생성 순서는 계약대로입니다. `idle`을 먼저 뽑아 일곱 가지를 눈으로 확인하고(1회 만에 합격),
**합격한 `idle`을 나머지 일곱 장의 첫 번째 참조 이미지로** 넣었습니다. 여기에 원본
`public/mascot/pose/idle.webp`와 포즈별 원본(`run` `jump` `sit` `think` `wave` `celebrate`)을
함께 넣어 정체성은 합격본에서, 자세는 포즈 원본에서 가져오게 했습니다.

`walk-2`는 `walk-1`을 첫 참조로 생성해 프레임 안 위치·크기·상체가 같고 다리와 팔만 다릅니다.
스프라이트는 **트림하지 않고** 1024 캔버스 그대로 96으로 줄였습니다 — 프레임마다 여백을
잘라내면 두 프레임이 어긋나 걷기가 떨립니다.

몸과 꼬리의 옅은 회로선만 뺐습니다.

## 계약과 달라진 것

1. **`nano_banana_2`라는 job type이 없습니다.** CLI에서 "Nano Banana 2"는 `nano_banana_flash`
   입니다 (`nano_banana_2`는 Nano Banana Pro로 잘못 매칭됩니다). `nano_banana_flash`를 썼습니다.

2. **`gpt_image_2`는 21:9를 지원하지 않습니다.** 지원 목록은 1:1·4:3·3:4·16:9·9:16·3:2·2:3.
   16:9 1k(1344×752)로 뽑아 **위쪽 하늘에서 80px을 잘라** 2:1로 만든 뒤 1024×512로 줄였습니다.
   위에서 자른 이유는 지평선을 하단 38%에 남기기 위해서입니다.

3. **아잉 스프라이트는 `gpt_image_2`로 만들었습니다.** 계약은 `nano_banana_2`를 지정했지만,
   참조 이미지를 넣으면 **입력 이미지를 픽셀 단위로 그대로 되돌려줬습니다**(2회 확인).
   `gpt_image_2`도 `image_references`를 받고 픽셀아트 변환을 제대로 수행해 이쪽으로 바꿨습니다.
   장당 4크레딧이라 비용은 계약 예산 안입니다.

4. **알파를 주는 모델이 없습니다.** 두 모델 다 불투명 3채널로 반환합니다. 계약의 접두·접미
   프롬프트를 그대로 쓰되 `flat solid pure magenta #FF00FF background`를 함께 지시해 균일한
   키 컬러 위에 그리게 하고, `sharp`로 로컬에서 키잉했습니다. 결과물은 전부 알파를 가집니다.

5. **스프라이트 프롬프트에서만 `no outline`을 뺐습니다.** 개정된 섹션 C가 그 규칙을 배경과
   소품에만 적용한다고 명시합니다. 아잉은 반대로 굵은 외곽선이 있어야 아잉입니다.

6. **`aing-idle`은 정면을 봅니다.** `walk-1`/`walk-2`만 몸이 오른쪽으로 틀어져 진행 방향이
   읽힙니다. 여덟 포즈가 정면~약간 우향으로 일관됩니다.

## 재시도한 것 (전부 성공, 3회 상한 안)

| 에셋 | 회차 | 이유 |
|---|:-:|---|
| `aing-*` 8장 | 2차 재작업 | 1차가 아잉이 아니라 일반 흰 고양이 — 헤드밴드·외곽선·체형 누락 |
| `aing-idle` (1차) | 3 | 1·2차 `nano_banana_flash`가 참조 이미지를 그대로 반환 → `gpt_image_2`로 교체 |
| `aing-walk-1` (1차) | 2 | 1차가 네 발로 걷는 옆모습이라 두 발로 선 나머지 7포즈와 어긋남 |
| `prop-3-1` | 2 | 1차 열쇠고리 뒤에 흰 종이 아티팩트 |
| `ground` | 2 | 1차에 위아래 빈 여백이 커서 풀·흙 띠만 잘라 재타일 |

2차 재작업에서는 `idle`이 1회 만에 합격해 재시도가 없었습니다 (8장 = 8잡 + `walk-2` 1잡).

후처리에서도 두 번 고쳤습니다. 처음엔 테두리 flood fill로 키잉했는데 **삼각대 사이·물레방아
바퀴살·열쇠고리 구멍처럼 닫힌 영역에 마젠타가 남았습니다.** 피사체에 마젠타 계열이 없으므로
전역 임계값 방식으로 바꿔 전부 제거했습니다.
